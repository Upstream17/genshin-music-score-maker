# 在「已落库的成品」上做用户点名的外科手术

适用：用户听完游戏内的效果，点名具体位置要改 —— 「1:56 那个 A5 删掉」「2:23 这块不要空，
**用低音声部那一行的重复填掉**」「**其他区域不要动**」。这是所有后续迭代的默认形态（比重新构建更常用）。

## 铁律

1. **改「曲库里当前那份 JSON」，不要从源 MIDI 重跑构建**。重跑会用新的启发式重新选声部，
   几十上百个无关的音会跟着变 —— 用户手里那份“已认可的东西”就被静默改掉了。
2. **先定位到具体按键事件再动手**：把 ±窗口（±2~3 秒）内的按下事件按时间列出来，带键字母、音高、
   按下时长。用户描述的时间误差常在 ±0.5s，不列出来就只能猜。
3. **动手前先扫全曲同模式并报数**：只改点名的，其余列时刻问一句是否一并处理。
4. **改完必须能证明「区外零改动」**（下面第 5 步），并在交付时把这个证明写出来。
5. **要重拨一个还在响的键，先把它的尾巴截短**（≥40ms 空隙）——
   否则同键重叠被 `convert` 合并，重拨直接消失。

## 接口与单位（踩过就白干半天）

| 函数 | 吃/吐 | 说明 |
|---|---|---|
| `m2.parse_smf(path)` | 吐 **秒** | 源 MIDI：`notes` = `(start, end, pitch, track, ch)` |
| `m2.decode_events(notes)` | 吐 **毫秒** | `(时刻, 键字母, 是否按下)` —— 键在**第 2** 字段 |
| `m2.press_intervals(ev)` | 吐 **毫秒** | `{键字母: [(按下, 抬起), …]}`，按**键**索引 |
| `m2.convert(notes, mode, transpose)` | 吃 **秒** | notes = `(start, end, pitch, 0, 0)`，顺序写反会卡死 |
| `m2.to_midijson(conv)` / `m2.verify_intervals` | — | 发射 D/U 串 / 强校验 |

键字母 ↔ 音高：`REV = {v: k for k, v in m2.KEYMAP.items()}`。

⚠ **别用 shell heredoc 写这类脚本**（`python - <<EOF`）：中文 + 反斜杠转义会被吞、字符串里嵌套双引号直接
SyntaxError，实测为此白跑了 3 轮。**用 `write_file` 写脚本文件再跑**；中文字符串内的引号一律用「」。

## 步骤

```python
import io, json, sys
sys.path.insert(0, "skills/genshin-music-scores/scripts"); import midi_to_midijson as m2
REV = {v: k for k, v in m2.KEYMAP.items()}

d0 = json.load(io.open(当前曲库JSON, encoding="utf-8"))
iv0 = m2.press_intervals(m2.decode_events(d0["notes"]))
P = sorted((s/1000.0, e/1000.0, REV[k]) for k, l in iv0.items() for s, e in l)   # 秒
```

**① 定位**（列出窗口内所有按键）→ 找到用户说的那个音（实录：`1:55.781  E5(E) 按1395ms`、`A5(Y) 按1395ms`）。

**② 删**：按 (音高, 时刻) 过滤掉那一条 press。

**③ 填空白 = 把「低音声部那一行」循环铺过去（不是把和弦同刻再按一遍）**

⚠ 用户明确否掉过「把空白开始时仍在响的和弦每 1.35s 重拨一次」这一版（几个音同刻再按下）：
「**不是让你填充一个同时按的音** …… 看这个空白处**前面低音区这一行**，看它**重复的那一段和声**，
**用这个低音声的重复填充**，**自然的衔接下一段**」。以下是改对后的可复制代码：

```python
GAP_MIN, PW, DUR = 1.5, 4.0, 0.22          # 空白阈值 / 估计脉冲的回看秒数 / 每个补音按多久

o = sorted({s for s, _, _ in P})
gaps = [(a, b) for a, b in zip(o, o[1:]) if b - a > GAP_MIN]
for a, b in gaps:
    near = sorted((s, v) for s, e, v in P if v <= 59 and a - PW <= s <= a)   # 低音区那一行（C3–B3）
    if len(near) < 4:
        continue
    ivs = sorted(y[0] - x[0] for x, y in zip(near, near[1:]))
    pulse = ivs[len(ivs) // 2]                        # 低音脉冲（实测 234ms = 八分音符）
    pat = [v for _, v in near[-6:]]                   # 最后 6 个低音 = 那一小节的音型
    t, i = a + pulse, 0
    while t < b - 0.05:                               # 铺到下一个音头前为止
        P.append((t, t + DUR, pat[i % len(pat)]))
        i += 1
        t += pulse
```

要点：
- 主旋律**不补**（它本来就停了）；内声部**也不补** —— 只续低音那一条线，低音声部听起来就像没停过。
- 每个补音只按 **~220ms**（低音声部本来就是短音，靠余韵连），不要给长时值，否则又变成一堆同刻长音。
- ⚠ 若补入的音与「空白开始时仍在响」的**同键长音**相撞，`convert` 会合并两段（补音直接消失）→
  先把那个长音的尾巴截到补音前 40ms（原段不足 30ms 就跳过，见上面铁律第 5 条）。
- 实测（《天路》4 处空白，最长 3.05s）：补入 40 个低音 → `>1.5s 空白 0 处`、总按键 978 → 1012、
  最大同按仍 4 键，且**区外逐键完全一致**（不需要截短任何尾巴）。

**④ 重发**：`conv, _ = m2.convert([(s, e, v, 0, 0) for s, e, v in sorted(P)], "raw", 0)` →
`ns, _ = m2.to_midijson(conv)` → 写一份**头部字段照抄 d0** 的 JSON（`ticks=1000`/`bpm=60` 别改），
`description` 里写清「本次改了什么」。

**⑤ 证明区外零改动**（跑脚本，别手算）：

```
python skills/genshin-music-scores/scripts/score_cli.py verify 新.json --diff-base 旧.json \
    --windows 115.5-117.3,138.0-141.0
```

输出三类：**区外逐键相等✓/✗**、**尾巴被截短的清单**（唯一合法的区外变动，要主动报给用户）、区内增删计数。
退出码非 0 = 有非预期差异，别落库。

**⑥ 跑常规强校验**：复刻重放 vs 纯 delta 偏差 0ms｜键 ⊆ 21 键｜事件时间单调｜>1.5s 空白 0 处。

**⑦ 交付**：覆盖同一个文件名（BetterGI 按 RelativePath 存设置，改名会丢），旧版备份在单曲工作目录，
然后**告诉用户用 `app/` 或进游戏听哪几秒、听什么**（mp3 只是 A/B 工具）。

## 交付话术（用户认这个）

- 先给他**改了什么**：删了哪个键（键字母 + 音高 + 时刻）、填了哪几处（每处用的**低音音型** +
  脉冲 + 铺入的音数/时刻表）——**别写成「用了哪个和弦」**，写「低音那一行铺了什么」。
- 再给他**没改什么**：「编辑区之外 927 个按键与上一版逐键完全一致」+ 唯一例外的 16 个截短尾巴清单。
- 最后给**待定项**：同模式但未授权改的那些位置（列时刻）。
