### 2.2 ⭐ `*<bpm>` = 变速标记（契约最大的漏洞）

BetterGI 源码 `MusicScoreParser.cs:391-401`：

```csharp
if (rawPart.StartsWith('*')) {
    if (!double.TryParse(rawPart[1..], NumberStyles.Float, CultureInfo.InvariantCulture, out bpm)
        || bpm <= 0)
        throw new FormatException($"无法解析 MIDI JSON 变速标记：{rawPart}");
    previousWasEvent = false;
    continue;                     // 不产生音符，也不推进 cursor
}
// 后续事件：delay = deltaTicks * 60000d / (bpm * ticks)   ← 用的是「当前」bpm
```

也就是 `*N` = **从此刻起把当前 bpm 改成 N**，后续 `Δticks` 用新 bpm 折算；它本身不占时间、不出声。

### 2.3 `@` 占位键

- `@` 出现 **11 442 次**，涉及 **147 个文件**。
- 全部是**单独占一个 token 的键位**：`D@` **1 006** 次、`U@` **10 436** 次。
- **`@` 与其它字母同 token 的情况 = 0 例**（不存在 `UZ@`、`D@Q` 这种）。
- 最高频形式：`U@0` **9 384 次**，其次 `D@0` 502 次、`U@30` 142 次、`U@24` 103 次。

BetterGI 语义（`MusicScoreParser.cs:415-440`）：`keys != "@"` 时才产生按下/抬起事件，但**`cursor` 照常推进**
（即 `@` 是"留白占位"）；`U@` 这一支被显式排除在 30ms 前移判定之外（`:424`）。

→ **契约要求"`@` 占位键按 BetterGI 语义处理"，结论就是：静默跳过、不发声，但时间轴照走；
并且不要把它记成 warning**（否则诊断面板会瞬间塞进 1 万多条）。

### 2.4 非法键：只有 `K`

- 出现在 **1 个文件**：`完整曲库/01_原琴JSON/卡农 - 7BRsrJmI.json`
- 共 **22 个 token**，`K` 永远单独成键，没有和其它键组合：`DK39|UK39|DK51|UK51|DK53|UK48|…|DK38|UK345`
- 全库 token 中用到的字母并集 = `ABCDEFGHJKMNQRSTUVWXYZ`（22 个）；
  **契约 21 键全部被用到**，多出来的唯一一个就是 `K`。
- BetterGI 行为：`keys.Select(char.ToUpperInvariant).Where(SupportedKeys.Contains).Distinct()` → **静默丢弃**。
  该曲因此少 11 对 K 事件（不影响其它音）。

### 3.6 yuanqin 的"默认时值/拍数规律"

- **没有默认时值**：每个音符 token **必须**紧跟 `[…]`，否则 BetterGI 直接抛
  `音符 X 缺少时值`（`:306`）。本库 22 245 个 token **没有任何一个缺 `[…]`**。
- 时值单位：`duration(ms) = 60000 / bpm * beatDenominator / 括号里的数`（`:651-658`），
  `beatDenominator` 取 `time_signature` **斜杠后的数**；括号里的数越大 = 时值越短。
- 方括号主数值的真实分布（22 245 个 token，**全部有值**）：

  | `[值]` | 16 | 8 | 4 | 2 | 32 | 6 | 1 | 15 | 3 | 64 | 17 | 5 | 7 | 12 |
  |---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
  | 次数 | **9 435** | **8 257** | **3 671** | 457 | 249 | 81 | 55 | 17 | 8 | 5 | 4 | 3 | 2 | 1 |

  → 实际是"**16 分音符为主、8 分为次**"，16 分与 8 分合计 17 692/22 245 = **79.5%**。`3/5/6/7/12/15/17` 这些非 2 的幂
  只在少数几首里出现（配合连音/装饰音写法）。
- `|` 与 `\n` **没有任何时间含义**，纯排版（解析器在 tokenizer 里跳过 `|`、在入口 `Replace` 掉 `\r\n`）。

## 8. 给实现者的落地清单（按优先顺序）

1. **`type` 缺失 / 为 null / 空串 → 按 `yuanqin` 解析**，并先 `.trim().toLowerCase()`。（否则丢 7 首）
2. **`midi` 分词先判 `*`**：`*N` 改当前 bpm（`N>0`，可小数），不产生音符、不推进时间；
   用 `Split('|', {removeEmpty:true, trim:true})`。（否则 51 首受影响、9 首节奏错）
3. **`@` 占位键静默跳过**：不发声，但**时间轴照常推进**（`cursor += delay`），**不要记 warning**。
4. **键统一转大写再过滤 21 键**（`K`、`@`、数字、`0` 全被丢弃），非法键只进 `warnings`，不 fail。
5. **`yuanqin` 时值后缀至少有 5 类**：`none`、`*`（×1.5）、`#`（1/16 拍）、`%`（bpm，本库 0 次）、
   连音 `\d+\.[36$]`（组，遇 `$` 收尾）；另外支持 `[^]`/`[&]`。**`-` 是分隔符，不是时值的一部分。**
6. **`keyboard` 预处理 4 步 + 括号语义**：`(` 同刻、`{` 错开 0.001 拍、`[` 均分琶音、`-` 每次 +1 拍、`>` 删除。
7. 数值解析一律用 `parseFloat`；缺省 `bpm=120`（须 > 0）、`ticks=480`（`max(1, round())`）。
8. `notes` 只有字符串形态（本库 0 个数组），但契约保留数组分支无害。
