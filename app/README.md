# 演奏台 — Genshin Music Score Maker（原神琴谱制谱器）

把 BetterGI 21 键曲谱直接在浏览器里弹出来 —— **不用开原神、不用开 BetterGI**。
还能用电脑键盘自己弹、就地改音符、按歌单连播。

```
双击 app/index.html（本地离线）  或  访问静态部署站点（https://yuanqin.upstream.eu.cc）
```

零依赖、零构建。本地 `file://` 直开零网络请求；通过 `http(s)://` 静态托管访问时，自动拉取 `library/manifest.json` 加载 18 首示范曲供访客试听。纸白底、墨字、单一青瓷绿强调色，纯扁平。

---

## 1. 怎么用

1. 本地双击 `app/index.html`（或打开在线部署站点）
2. 在线访问会自动载入 `library/` 中的 18 首示范曲；本地 `file://` 打开时把 `library/` 或你的曲谱目录**拖进页面**，或点「导入曲谱 / 整个文件夹」
3. 点曲目 → 空格播放

左栏是歌单，中间是演奏台，设置与诊断收在左栏底部「＋音色与设置」里。

---

## 2. 三个模式与功能

### 演奏与播放控制

| 操作 | 说明 |
|---|---|
| 播放 / 暂停 | 按钮 或 `空格` |
| 重置 / 停止 | 按钮 或 `Esc`（播放回到开头，停止发声） |
| 上一首 / 下一首 | `↑` `↓` 或 `◀ ▶` 走带按钮 |
| 播放模式三模切换 | 点击播放模式按钮交替切换：**列表循环** ➔ **单曲循环** ➔ **顺序播放** |
| 速度 0.5×–2× | **变速不变调**（改的是调度时间轴，不是 playbackRate） |
| **热更新（Plan B）** | 本地修改 `.json` 后直接拖拽进页面，原位覆盖热更新，无需重启网页或重置播放视图 |

界面实时显示：21 键三排高亮、当前音名与唱名、音符合成卷帘（点击可跳转时刻）。

### ⌨️ 键盘弹奏

**直接按电脑键盘就能弹**，映射与原神一致：

```
上排 Q W E R T Y U  =  C5 D5 E5 F5 G5 A5 B5
中排 A S D F G H J  =  C4 D4 E4 F4 G4 A4 B4
下排 Z X C V B N M  =  C3 D3 E3 F3 G3 A3 B3
```

按键即响、即亮。开关直接整合在「音符」同排工具条中（「键盘弹奏」勾选框及快捷键提示），节省垂直屏幕高度；不需要时取消勾选即可。

### ✎ 编辑模式

在卷帘头部点击「编辑」按钮（与「演奏」同排胶囊切换），卷帘即变为交互编辑画布：

- **鼠标拖拽音符** → 按住音符可在时间（横轴）与 21 键音高（纵轴）之间自由拖动，即时试听
- **拖拽边缘改时长** → 鼠标悬浮在音符右边缘（光标变为 `↔`），拖拽即可拉长或缩短时值
- **鼠标滚轮漫游** → 卷帘上滚轮直接横向平移时间轴；`Ctrl + 滚轮` 放大/缩小时间窗口
- **中键 / 右键抓取** → 按住鼠标中键或右键在画布上拖拽平移视口
- **网格吸附（Snap）** → 支持 20ms、50ms、100ms 及 1/4 拍、1/8 拍节拍吸附
- **键盘微调（不切歌）**：
  - `↑` `↓` → 选中音符上下移动一个音级
  - `←` `→` → 选中音符左右平移一个网格单位
  - `Shift + ← / →` → 伸缩选中音符时长
  - `QWERTY...` 键字母 → 将当前选中音符直接改为对应琴键
  - `Esc` → 取消选中音符
- `◂ 前移 / 后移 ▸` → 按钮按网格平移起始时间
- `◂ 音高 / 音高 ▸` → 按白键音阶上下移动
- `◂ 时长 / 时长 ▸` → 时值 ×1/1.5 或 ×1.5
- `删除` 或 `Delete` / `Backspace` 键
- `撤销` 或 `Ctrl+Z`（最多 60 步）
- `还原` → 丢弃所有修改，回读原始文件
- `导出 JSON` → 下载改好的曲谱

> 导出格式是 BetterGI 的 `type:"midi"`（`bpm:60` + `ticks:1000`，即 1 tick = 1 ms），
> 直接用 BetterGI 就能弹。**只动内存副本，不会改你磁盘上的原文件。**

## 3. 音色

### 3.1 默认：7 套真实乐器采样

默认音色就是**真实采样**（风物之诗琴），不再是合成近似。已清理冗余旧版与历史遗留合成项，下拉框保留 7 套精选真机音色：

| 音色 | 说明 |
|---|---|
| **风物之诗琴** | 默认（`samples.js`，随页面加载） |
| 老旧的诗琴 / 镜花之琴 | 诗琴系列 |
| 谐律键琴 / 跃律琴 / 悠可琴 / 余音 | 需切换时按需加载 |

- **来源**：开源项目 [WindsongLyre-Simulator](https://github.com/JularDepick/WindsongLyre-Simulator.fork)
  的 `instruments/<id>/audio/`（每个乐器 21 个音，与 21 键一一对应）
- **转码**：`ffmpeg -ac 1 -ar 44100 -c:a libmp3lame -b:a 48k -t 2.2`
- **体积**：7 套共约 1.5 MB，其中默认那套约 344 KB；其余 6 套**只在切到它时才加载**
- **可复现**：`python app/tests/gen_samples.py <各乐器目录> app/js`

> ⚠️ **音频版权归 miHoYo 所有。** 这里只是把它们放进你本机的项目里自用，
> **请不要提交到公开仓库，也不要分发给别人。**
> 删掉 `js/samples.js` 与 `js/samples-*.js`，播放器会自动回退到内置合成音色（竖琴、钢琴、八音盒），其余功能不受影响。
> `谐律键琴` 原始素材缺 6 个音（15/21），缺的音用最邻近采样变调顶上。

### 3.2 换成你自己的采样

左栏「＋音色与设置」→「加载自定义采样文件夹」。支持任一命名法：

| 命名法 | 例子 |
|---|---|
| 科学音高记号 | `C3.wav` `A4.mp3` `C#5.wav` |
| 原神键字母 | `Z.wav` … `U.wav` |
| MIDI 音高号 | `48.wav` … `83.wav` |

缺哪个音，会用最接近的采样变调顶上（不会哑掉）。加载后会出现在音色下拉里「自定义采样（本次）」。

### 3.3 内置合成音色（公开版默认 / 备用）

`audio-engine.js` 内置 `windsong` / `harp` / `piano` / `musicbox` 四种合成音色；界面下拉列表中展示 **竖琴（`harp`）/ 钢琴（`piano`）/ 音乐盒（`musicbox`）** 三项。
在没有 `samples*.js` 的公开开源仓库或 Cloudflare 静态站上，页面会自动以内置合成音色开箱可用（默认 `竖琴`），并提示可在下方加载自定义采样文件夹。

## 4. 支持的曲谱格式

完全按 BetterGI `MusicScoreParser` 语义复刻，支持三种 `type`：

| type | 形态 |
|---|---|
| `midi` | `DG100\|DQ0\|UW0\|…` —— `D`=按下 `U`=抬起，后面是相对上一事件的 tick 增量 |
| `yuanqin` | `Z[4]Z[4]B[4]\|N[2]…` —— `[n]`=时值，另有 `%`/`^`/`&`/`.`/`$`/`#` 等标记 |
| `keyboard` | 字母键谱 —— `-`=延长、`(…)`=和弦、`[…]`=琶音、空格/`0`=休止 |

`.mid` 需先用 `tools/add_songs.py` 转成 JSON。

## 5. 目录结构

```
app/
├── index.html               ← 双击它（CSS 已内联在这个文件里）
├── js/
│   ├── bettergi-parse.js    三 type 解析器（window.BGIParse）
│   ├── audio-engine.js      Web Audio 引擎 + 采样加载（window.BGIAudio）
│   ├── samples.js           ★ 音色清单 + 默认音色（风物之诗琴，base64；不进 git）
│   ├── samples-vintage_lyre.js 等 6 个文件（其余 6 套音色，按需加载；不进 git）
│   └── app.js               界面 / 调度 / 键盘弹奏 / 编辑 / 歌单
├── tests/
│   ├── integration.test.js  契约 + 全库不变量
│   ├── parse.test.js        解析器全库回归
│   ├── audio.test.js        音频引擎 / 文件名→音高映射
│   ├── realtime.test.js     ★ 真实时间端到端（CDP）
│   ├── ui.test.js           ★ 新功能验收（音源/键盘弹奏/编辑/连播）
│   ├── headless.html        无头 DOM 端到端
│   ├── screenshot.js        真实时间截图工具（开发用）
│   └── gen_samples.py       采样 → samples.js 生成器
└── README.md
```

**没有构建步骤。所有 js 都是 classic script** —— 因为浏览器在 `file://` 下会拦掉
ES module 和 `fetch`，而「双击就能用」是这个工具的核心价值。

**CSS 为什么内联进 HTML**：部分 IDE / 编辑器的内嵌网页预览常常只放行
`<script src>`，却拦掉 `<link rel="stylesheet">`（或给它错误的 MIME），结果就是
「页面渲染出来了、但完全没样式」。内联之后页面只剩 4 个 JS 请求，内嵌预览与双击 `file://` 都能正常显示。

## 6. 验证

### 6.1 跑测试

```powershell
node app/tests/integration.test.js            # 契约 + 全库不变量
node app/tests/parse.test.js library          # 解析器示范曲库（18 首）
node app/tests/audio.test.js                  # 音频引擎
node app/tests/realtime.test.js               # 真实时间端到端（需 Chrome）
node app/tests/ui.test.js                     # 音色 / 键盘弹奏 / 编辑 / 连播（需 Chrome）
```

浏览器里按 F12 可跑 `BGIParse.selfTest()` / `BGIAudio.selfTest()`。

### 6.2 当前结果

| 测试 | 结果 |
|---|---|
| `integration.test.js` | **62 PASS / 0 FAIL** |
| `parse.test.js library` | **18/18 解析成功**，20,551 音符，不变量 0 违反，selfTest 53/0 |
| `audio.test.js` | **165 PASS / 0 FAIL / 3 SKIP**（skip 均为「Node 无 AudioContext」） |
| `realtime.test.js` | **32 PASS / 0 FAIL** |
| `ui.test.js` | **62 PASS / 0 FAIL** |

关键实测：

- **真实采样**：`21/21 音` 解码成功，音色自动切到 `sample`
- **运行时零网络**：页面只发 `file://` 请求，`http(s)` **0 个**
- **播放头速率**：1.0× → 实测 1.00–1.10×；2.0× → 实测 2.00×；拖到 60% → 跳 22.2s / 36s
- **键盘弹奏**：按下 `Q` 后该键 `--e` 从 0 升到 0.70，松开后衰减到 0.09；关闭开关后不再触发
- **编辑**：点空白新增（42→43 音）、改音高（B3→C4）、改时长（320→480ms）、删除、撤销、还原，全部逐项通过
- **连播**：把曲目跳到 97.5% 后播放，曲终**自动切到下一首**（卡农 → 小星星）

### 6.3 设计约束（改样式时别破坏）

1. `#keyboard .key` 必须有 21 个，且当前按下的键要带 `.on` 类（测试与无障碍都依赖它）。
2. 键盘视觉由 CSS 变量 `--e`（0–1）驱动，**与 `.on` 解耦** ——
   这样停止时 `.on` 立刻清掉（不残留），而视觉还能平滑收尾。
3. 进度条是「自绘轨道 + 隐形原生 `<input type=range id=seek>`」，
   语义仍在原生 input 上（`value` / `input` / `change` 都可用）。
4. 所有动效只用位移与透明度，120–200ms；不缩放弹跳、不用阴影发光（扁平要求）。
5. 尊重 `prefers-reduced-motion`。

## 7. 已知限制

1. **只读 JSON**，不转换 `.mid`（转换是 `tools/` 的活）。
2. 渲染的是「按什么键、什么时候按」，**不含** BetterGI 的 `InputMode` 差异与投递延迟。
3. 编辑导出统一转成 `midi` 型（1 tick = 1ms），会丢掉原文件里的 `type`/装饰音等记号；
   原文件不动，随时可「还原」。
4. 所有浏览器端验证都在 **Chrome 无头模式**做的（真实 `AudioContext`、真实 `decodeAudioData`、
   真实时间 CDP）。**真实声卡输出、真实鼠标拖拽文件夹、Edge** 没有实测过。
5. 307 首全量导入时的内存与帧率没有实测（单文件最大 8013 事件、最长 512 秒）。
6. **音色好不好听没有自动化验证**：频谱、RMS、频率误差都测了，但「像不像原神」只能你自己听。
