# 多轨 GM 编曲 MIDI → 主旋律 → 原琴 21 键

## 什么时候走这条路
源 MIDI 不是「双手钢琴谱」也不是「单轨旋律」，而是**十几轨的 General MIDI 编曲**：鼓轨 + 贝斯 + 钢琴 +
好几件旋律乐器（萨克斯/小号/口琴/哨笛/弦乐/电吉他）**轮流演奏同一条主旋律，各自用自己的八度**。

判据（`tools/add_songs.py --list-tracks <file.mid>` 的输出就能看出来）：
- 打出十几行，每轨一个独立通道（`通道 [0] [1] [2] …`）；
- 音符数从几十到上千不等；音域从 33 一路铺到 96；
- **有一条音符很多的轨在整个列表里「没有」Program Change** —— 那是通道 9 的 GM 鼓轨。

⚠ 别把整条钢琴轨直接转（实测密度 5.5 音/秒、八度折叠 325/1231 = 27%、最大同按 9 键 → 糊）。

## 第 1 步：认轨（每轨的 GM 音色）
扫 Program Change（状态字节 `0xC0|ch`，只带 1 个数据字节）。直接用
`scripts/list_midi_gm_tracks.py <file.mid>` —— 它一次打出「通道 / GM 音色名 / 音符数 / 音域 /
每 onset 单音比例 / 10 秒桶活跃区段」，判据全在输出里。

- **通道 9 = GM 鼓轨**（0-based；有的工具显示成 10）。它**没有 Program Change 事件**，这本身就是指纹。
  **必须整轨排除**，否则它是「音符数很多、单音比例也不低」的轨，很容易被当成旋律轨。
- **轨 0 通常只有 meta（conductor）**，没有音符 → `--list-tracks` 只打「有音符的轨」，**那边的轨号是索引 +1**。
  自己写脚本按 0-based 索引算，别按显示号算，否则差一轨。
- 音色名直接给角色：
  | GM 音色 | 角色 |
  |---|---|
  | Acoustic Grand Piano | 旋律 + 伴奏**混在一起**，别整轨用（要拆就取每 onset 最高音） |
  | Fretless/Electric Bass、Contrabass | 贝斯（见第 7 步的坑） |
  | Clavi、Acoustic Guitar (steel)、每 onset 正好 3 个音的琶音 | 伴奏织体，不是旋律 |
  | Alto Sax / Trumpet / Harmonica / Whistle / Choir Aahs / String Ensemble / Electric Guitar | **旋律乐器**（实际是哪几件要看第 2 步） |

## 第 2 步：确认「旋律在乐器间轮换」
1. 统计每轨**每 10 秒桶的活跃度**。旋律乐器的活跃区段**首尾相接、基本互不重叠** → 旋律在传递。
2. 按 onset 排序打印每轨的音序列（每 onset 只显示最高音）。几件乐器的序列会呈现**同一条旋律的不同八度 /
   不同装饰**——这是判定「它们都是主旋律」的直接证据，比猜音域可靠。
3. ⭐ **同音色 + 同音域 + 同音数的两条轨，先查「延迟回声」再当二重奏**。老 GM 编曲（PsmPlayer 时代那批）
   常把整条主旋律复制一份、往后挪约一个八分音符当回声轨。判据：拿 B 轨每个音的 `(时刻, 音高)`，
   去 A 轨里找 `t − Δ`（Δ≈0.25s）处是否存在**同一个音高**，命中率高 → 就是回声，**整轨丢掉**。
   ⚠ 别用「同刻同音高」的比例判独立性：实测只有 **29/191 = 15%** 同刻，看着像两条独立声部，
   其实 B 每个音都等于 A 在前一个八分音符处的音。留着它 = 旋律每句拖一个影子。
4. 认轨不能只看 `--list-tracks` 的角色名：同一件乐器可能既是主旋律又是伴奏织体里的一员，
   **最后一句定论必须落在「打印音序列对拍」上**，表格只用来缩小范围。

## 第 3 步：合并成单声部
- 主旋律 = 所有旋律乐器轨的**并集**。
- **去重规则：`(onset, 音高)` 相同、起始差 <100ms 的只留一个**（取更长的那个 end）。
  多件乐器叠同一条旋律时起始常错开 **30–50ms**（同一音高成对出现）。
  这个窗口**不会吃掉真实重复音** —— 该速度下重复音至少隔一拍（实测四分音符 0.77s、八分 0.385s）。
- 合并后应接近单声部（实测 371 音 / 379 onset ≈ 0.98 音每 onset）。
- ⭐⭐ **整曲里「旋律」会换轨 —— 逐段定，别拿一条轨串全曲**。乐队总谱的常见三段：前奏（器乐）/
  人声段（人声轨）/ 间奏·solo 段（主音吉他轨）。实测《加州旅馆》6:34 那首：
  **0–54s 前奏 = 分解吉他轨每音头顶部 3 音**（前奏本身没有「旋律」，琶音就是主角）、
  **54–260s = Vocal 轨每音头最高音**、**260s 后 solo 段 = E.Guitar 轨每音头最高音**。
  判据：先把每轨的活跃区段拉出来看**哪条轨在这段里响**（第 1 步的 10 秒桶活跃度），再按段取轨；
  拿「全曲最高音」当旋律会让前奏/间奏的伴奏音冒充旋律。

## 第 4 步：覆盖 + 复现度自检（不用耳朵也能验）
- **全曲不能有 >1.5s 的空档**（`结束时刻 → 下一个起始` 排序后扫一遍）。有空档 = 漏了某个旋律乐器轨。
- **同一个乐句必须在不同段落逐音重复 3–4 次**。若抽出来的「旋律」是一次性、不复现的音符流 → 抽错轨了。

## 第 5 步：音区（关键抉择，别自己拍）
同一旋律被不同乐器演奏时各用自己的八度 → 抽出来的线会**逐句跳八度**。两条交付，让用户耳朵定：
- **忠实版**：保留原编曲的八度（= 源 MIDI 的原样）。
- **统一八度版**：逐乐句对齐到一个音区，更像「一个人在唱」，更连贯。

统一的做法：**按「轨切换 或 间隔 >1.2s」切乐句** → 每句算中位音高 → 整句 ±12 移到目标音区；
≥3 音的乐句才自己算，短乐句沿用上一句的移量（否则交界处乱抖）。

三个反例，别踩：
- ⚠ **别逐音取「离上一个音最近的八度」（running target）** —— 会缓慢向下漂移，实测整首从 G4 漂到 C3，
  把旋律推进低音区。
- ⚠ **别把整条旋律硬折进一个固定 ~20 半音的窗口** —— 最低音和最高音会相撞、轮廓反转（旋律常跨 25–30 半音）。
- ⚠ **段落的八度差不一定只是编曲随手写的**：多段体里引子/副歌本来就高八度。**先跟权威谱对一遍**（见下），
  再决定要不要统一 —— 盲目统一会把本来该高的引子按下去。

## 第 6 步：移调到 C 大调 + 转换
- ⭐ **第一步是跑移调扫描表，不是读直方图**：对偏移 −6…+6 各算「黑键音占比 / 折叠后可演奏率 / 折叠数」。
  **黑键 0% 那一行就是无损解**（说明该曲音级正好是一套大小调音阶的 7 个音），选它，再在 ±12 同余类里挑音区。
  实测《江南》原调 Bb 大调：原样黑键 37.5%、可演奏率只有 62.5%；**+2 后黑键 0%、100% 可演奏**（+2 与 −10 同余，
  取 −10 是因为旋律正好落进 67–81）。对外就说「这首是降 B 调，琴只有 C 调白键，整首升一个全音——音程不变」。
  ⚠ 对照方案只有 `snap`，它会改掉 37.5% 音的音高（旋律变形）；**能整首移调就别用 snap**。
- **判调性**：按**时长加权**的 pitch-class 直方图 + 逐根音算「音落在该调 7 个音上的时长比例」，
  **大调/小调一起报**（同套音要一起看：`{3,5,7,8,10,0,2}` = Eb 大调 ≡ C 小调）。
- 移调量 = `(0 − 主音) mod 12`，可再加 ±12 选音区；**只能整八度叠加**，非 12 倍数会改音名（见 SKILL §8.2b）。
- `m2.convert(notes, "snap", transpose)` + `verify_intervals`；note 元素顺序 `(start, end, pitch, track, ch)`。
- 移调后仍在调内的音几乎零吸附（实测 Eb→C 只吸附 10/371），折叠也少 —— 比 snap 半音划算得多。

## 第 7 步：要不要补低音
⚠ **GM 贝斯轨装不进琴的低音八度**：琴的低音区是 **C3–B3，只有 12 个半音**，而贝斯轨常跨 13+ 半音
（实测 A#1–A#3），移调又只能整八度 → 要么整轨跑进中音区撞旋律，要么把最低几个音折叠上去、低音线呈**锯齿**。
→ 想「旋律 + 低音」必须**先把旋律统一八度再整体抬 12**，低音区才空得出来；否则老实只交旋律版。
- **跨 2 个八度的贝斯折进单一 C3–B3 时，最低那几个音会被整体抬 +24**（例 G1→A3），低音线**局部轮廓反转**
  —— 这是几何必然（12 个半音装不下 24 个），不是 bug：**音级、和弦进行、音程全保持原样**，只是那几个音的八度变了。接受它。
  ⚠ 别为「保住轮廓」去逐音选最近八度（running target）—— 会整首向下漂移（见第 5 步反例）。
- 折进低音八月的实现：`while v < 48: v += 12` 再 `while v > 59: v -= 12`（按音级折叠，不是按距离找最近）。
补低音更稳的来源是**钢琴轨每 onset 的最低音**（限制在原始 ≤ 大三度以下的音），每 350ms 最多留一个、
时长封顶 1.2s，避免长低音互相叠成 6–7 键同按。
⭐⭐ **多层缩编必须逐层节流，别「每个音头都补」** —— 一整首 6 分钟的歌逐音头补（旋律+伴奏+低音）= 密度炸到
**10.0 音/秒**（实测 3951 音），琴上就是一片糊。**先算预算再写代码**：目标 4–5 音/秒 ⇒
**总音符 ≈ 时长 × 4.5**，按层分配 —— 旋律原样（1.9–2.0/s）+ 伴奏**每 ≥0.3s 最多一个音** +
低音**每 ≥0.6s 一个、时长封顶 1.2s（按同键封顶，见 SKILL §8.2b-3.5）**。
实测按这个节流：393s 的歌 2127 音 → 合并后 **1953 个按键区间 / 4.97 音/秒 / 最大同按 6 键 / 21 键全用到** ✓。
⚠ 「每 350ms 一个」只是**单条低音轨**的说法：旋律 / 伴奏 / 低音三层叠加时，**每层各自的间隔都要单独设**。
⚠ **低音必须避开旋律的键**：`convert` 合并同键重叠区间时按下时刻取**最早**那个 → 若低音与某条旋律音同音高
且重叠，旋律的击弦就被吞掉、起点被拉早（实测 342 个低音里 **77 个**中招，旋律最多早 385ms）。
**规则：低音让路** —— 同音高且重叠的低音直接删。删完再跑一遍「合并数不为 0 就排查」。
⭐ 实现三细节（实测一次过）：
  a. **在「折叠后的键」上判冲突**，不是在源音高上判 —— 两个源音高差一个半音，折进 48–83 后可能落到**同一个键**；
  b. **优先截断、其次删除**：把伴奏音截到「旋律音起点 − 30ms」，截完不足 60ms 就直接丢（别留一个听不见的点）；
  c. **按段报被吞比例** —— 实测《加州旅馆》：前奏（快速琶音、同键反复多）**12%** / 人声段 **2%** / solo 段 **9%**。
     全部为 0 不可能；**「用户最在意的那条旋律线」接近 0 才算合格**，琶音/华彩段的同键反复被吞属琴的物理限制，
     如实报数即可，别为了凑 0 去砍伴奏。

## 装配顺序与两个自查
每声部各自变换、再合并（全曲统一移调只适用于单声部源）：
1. 每声部各自 `fold(note + 2 − 12)`，或贝斯折进低音八度（`while v < 48: v += 12; while v > 59: v -= 12`）；
2. 低音让路（同键重叠的低音删掉）；
3. `m2.convert(notes, "snap", 0)` 合并同键 —— **此时必须报「八度折叠 0 / 半音吸附 0」**，
   不是 0 就说明前面的移调量算错了（这一步同时是「无损」的证明）；
4. **首音平移放在「整毫秒事件层」做**：把所有事件的毫秒整数统一减 `首音ms − 300`，
   不要在秒的浮点区间上加减（浮点取整会打散同刻事件的巧合，破坏 `U@0` 插入条件）；
5. `to_midijson` + `verify_intervals`（偏差应 0ms）。
   ⚠⚠ **单位陷阱：`parse_smf` 返回秒，`convert` / `to_midijson` / `verify_intervals` 也**全部吃秒**。**
   中间用毫秒算过一轮再喂回去（漏了 `÷1000`）会**「校验照样 OK」** —— 因为比对两边用的是同一套错单位，
   但成品首音变成 **340909ms**、`render_preview` 会去申请 **74GB** 内存直接崩。
   自查两条：成品**首音 ≈300ms**（裁空拍之后）、**跨度 ≈ 源时长 ±10%**；对不上先查单位，别去查算法。

**两个自查** —— `verify_intervals` 抓不到，因为它比对的是「合并之后」的目标区间：
- **旋律击弦位移**：拿合并前每个旋律音的**意图起点**，去成品里同一个键的区间里找对应，**偏差 >2ms = 被吞或被提前**。
  ⚠⚠ **比对前必须把平移量减掉**：`tgt = 源起点ms − d`，`d = 首音ms − 300`。漏减 `d` → 所有音都「错位」、
  误报成 100% 被吞（这是本流程最常见的两次自伤之一：一次是**秒/毫秒单位**，一次是**漏减 `d`**）。
  合并数不为 0 ≠ 有问题：实测「旋律+钢琴+低音」有 69 对跨声部同键重叠，但旋律位移仍是 0（因为同刻重叠，取最早 = 原起点）。
- **跨声部同键真重叠对数**：打印出来逐对看 —— **同刻重叠无害**（合并后起点不变），
  **起点早于旋律才有害**（旋律击弦被吞）。
不管过不过，对外报告要带这两个数（「旋律位移 0 处 / 跨声部重叠 N 对」），而不是只说「校验 OK」。

## 用权威谱交叉核对（性价比最高的一步）
内部校验（按键合法 / 时间单调 / 按下区间逐键一致）**只能证明「忠实于源 MIDI」，证明不了「这是这首歌的旋律」**。
抽取多轨旋律后一定要对谱：
1. 把旋律转成**首调级数**（移调到 C 后 `p % 12` → `1..7`，`p//12` 标高低音点），打印成简谱串。
2. 跟公开的 C 调简谱逐音对：`17jita.com/tab/num/<id>.html`（图片谱）、`zuoqu.com`、`haijt.com`；
   吉他/尤克里里和弦谱（ultimate-guitar、guitarians）给的是**调号 + 每小节和弦**，用来确认调性与移调量。
3. ⚠ `data.17jita.com` 上的谱图**有防盗链，直接取 403**。用
   `curl -sL -e "<简谱页 URL>" -A "Mozilla/5.0 …" -o jianpu.png "<图片 URL>"` 下到本地（写 scratch 目录），再读图。
4. 读图**分带裁切**：整页密集吉他谱一次喂给视觉模型会超时，按 300–600px 高的条带逐条读；
   只读你实际看到的数字，别让它推测。
5. 简谱自己有排版噪声（前奏、反复记号、倚音、歌词错位），**只用来确认乐句骨架**，别当逐音真值。

⭐ **快路：用「歌词锚点 + 搜索摘要」，别一上来就下谱图读图**。搜 `"<曲名> 简谱 <歌词片段>"` ——
结果的**摘要里常常直接带出「歌词逐字对齐的级数」**（如某简谱站片段 `… 3 雨 | 3 3 圈圈圆圆圈圈`），
一眼就能对上，完全绕开防盗链与分带读图。
**歌词锚点法**：挑副歌里那句**同音反复的排比歌词**（连续 6+6 个字唱在同一个音上），
源 MIDI 的对应位置应出现 **N 个连续同音高** —— 实测《江南》「圈圈圆圆圈圈天天年年天天」= 12–13 个连续 D6，
移调后 = 音级 3，与简谱的 `3 3 3 …` 对上。**一次同时证明三件事：是这首歌 + 抽对了轨 + 移调量对。**
其次用吉他/尤克里里和弦谱（ultimate-guitar、guitarians）读**调号 + 每小节和弦**：同一首歌在不同网站会写成不同调
（实测同曲有的写成 G 大调、源 MIDI 是 Bb 大调），**和弦级数（I/IV/V/vi）对得上就没问题，绝对调号不用强求一致**。

⭐⭐ **有文本简谱就直接读文本，别读图**：`jianpu.space`（簡譜空間）的曲目页把「级数 + 歌词逐字对齐」
渲染成 DOM 文本 —— 浏览器打开后 `document.body.innerText` 一把抓下来就是完整简谱（零防盗链、零视觉模型、
`web_extract` 抓不到但浏览器能开）。⚠ 它**从第一句唱词写起，不含器乐前奏** → 前奏的结构/长度要用**全曲版 MIDI** 量。
拿到的级数串直接做**子序列定位**：把主歌每句的公式（实测《江南》`6715316` / `7771756` / `66715316` / `77712175`）
在成品的级数串里搜位置 —— 一眼看出「8 句只用了 4 条旋律」「第 1 句在第 1/5/7 句复用」。
这既是结构核对的硬证据，也是回答「前面怎么这么多重复」的依据（见 SKILL §5.5）。

⭐ **两版编曲之间对齐 → 用「级数序列 DTW」**：把两版各自「每音头顶声部 → 首调级数」排成序列，跑一次 DTW
（代价 = 级数不等记 1；700×1000 的矩阵秒级出结果）。三个用途：
① **代价 / 序列长度 < ~0.4 ⇒ 结构与旋律确实对得上**，可以放心对用户说「我这一版是忠实的」；
② 回溯路径 = **段落对应表**，直接量出两版的速度比；**比值在各段是否恒定** ⇒ 区分「只是快慢差」还是「段落被删」；
③ 定位副歌/前奏在两条时间轴上的位置，用来核「前奏到底走了几遍」。
实测《江南》：光遇版 0–42s ↔ 全曲版 2.0–51.2s（正好 = 前奏两遍 + 主歌八句），路径比值 1.10–1.22。
⚠ 旋律抽取不准时 DTW 会退化（一条音被拉到几十个音上）：先看**代价率**，难看就先去修「顶声部是不是旋律」。

实测价值：核对确认抽出的 `1 3 5 1 | 7̣ 3 5 5 | 6 7 1 6 | 5 …` 与 C 调简谱逐音吻合（多出来的 `4` 是源 MIDI 的
半音滑音被吸附所致），一次同时验证了「抽对了轨」和「移调量对」。

## ⚠ 最容易漏的一步：短半音倚音簇要「整簇删除」
源里的**半音接近音**是固定句式「长音 → 短音 → 黑键短音 → 长音(目标)」（实测 `E4(385ms)→F4(96)→F#4(96)→G4(955)`。
四种做法用户逐版听过：吸附 → `F4→G4` 隔 96ms（假连音 ✗）；只丢黑键 → 隔 199ms（✗「还是怪」）；
折成同刻和弦 `(F4+G4)`（✗「滑音好怪」）；✅ **整簇删除（含簇内调内短音）→ `mi→so`（用户定案）**。
**只对含黑键的短音簇触发**（≦250ms、间隙<150ms）；全白键的 `6̣7̣1` 拔句原样保留。详见 SKILL §4b3.5。
⚠ **删完还要把时间还回去**：目标音起点提前到簇首 —— 否则会露出空档（实测 `E4→G4` 拉开 **597ms**，
用户会说「是不是稍微有点长」）。归还后回到 385–397ms（一个八分音符）。
自查：成品的**相邻按下 10–260ms** 的对，除源谱自带的 grace run 外都应消掉。

## ⚠ 第二个易漏项：源 MIDI 的前导空拍
实测该曲**全部 17 轨第一个 note-on 都在 tick 960**（div=120 ⇒ 2 小节 = 6.15s）——文件是从第 3 小节才开始写的。
不裁的话 BetterGI 一按播放先干等 6 秒，用户会问「为什么开头一大段空白」。
做法：**只在第一个事件的 delta 上做整毫秒平移**（`delta0 -= 首音ms - 300`），其余事件一个字节不动（详见 SKILL §4b6）。
