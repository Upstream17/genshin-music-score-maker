# 转调的歌 → 原神琴改编（路线与代价）

## 为什么「转调」是硬墙，而不是音域问题
原神琴是**固定音高**乐器：21 键 = C3–B5、只有 C 调 7 个白键。一首歌若**中途转调**（同一段旋律在几个调上唱，
华语流行/民族风常见「连升两次调」），各段用音的**音级并集**会超过 7 个 → 琴上根本没有那几个音。

算例：三调相差五度（A 大调 → E 大调 → B 大调），整首搬到 C 大调后相当于 **C 大调 ∪ G 大调 ∪ D 大调**
= `{C,D,E,F,F#,G,A,B,C#}` = **9 个音级**，其中 **2 个（F#、C#）在白键之外**。
→ 这几个音只能 ① 挪半音（听起来跑调）或 ② 改声部/换和声。**转调越远（差全音、差小三度），白键外的音越多。**

## 判据：怎么知道这首歌转调了
按可靠性排序，全都不用扒谱：
1. **谱面**：简谱里出现「转1=X」「1=E」这类标记；或同一段旋律重复出现但每遍调号不同。
2. **乐谱站说明**：搜索结果的摘要里常有「采用了中国调式…**同样一段旋律，连升两次调**」。
3. ⭐ **演奏教学帖**：搜「<曲名> 二胡/古筝/合唱 怎么拉 / 几个调 / 音域」—— 器乐要换指法时作者一定会写清调性结构，
   顺带给出**音域度数**（例：某二胡贴写「转调后音名跨度为五度，实际音域从十度提高到十二度」）。
   这是**用最少力气拿到「调号 + 转调 + 音域」三项**的路径，比找 MIDI 快得多。
4. **数据侧**：有 MIDI 时，按 pitch class 统计全曲用音，**> 7 个音级 = 必然转调**（也顺便暴露半音装饰音，别混为一谈：
   装饰音是零星几个，转调是成段成块地换）。

**音域闸先算再答**：琴有 36 个半音，流行歌通常 1–2 个八度（十度～十二度 ≈ 16–19 个半音）→
音域**几乎从来不是真障碍**。用户往往担心音域，真障碍是调性 —— **先量再答，并明确说出他猜错了方向**。

## 三条改编路线（都要渲 mp3 让用户耳朵定）
| 路线 | 做法 | 代价 |
|---|---|---|
| **A 一律放平** | 三段都写在 C 大调白键上（整首按第一段的调移调） | 每个音都准、一定能弹；**丢掉「一遍比一遍高」的推进感** |
| **B 用音区代替调性**（推荐） | 各段分别占琴的低/中/高音区，用**音阶内的升移**近似原曲的升调 | 推进感保住；每段会多出 1–2 个白键外的音，只能挪半音 |
| **C 只做一段** | 只留第一段，或只做副歌高潮段 | 最干净最好听，但不再是「整首」 |

**B 的关键：把「升调」翻译成「升音级数」**。琴上能走的整音级升移有：
- `do→re` = +2 半音（= 原曲升全音，**正好挡在白键外，不可用**）
- `do→mi` = +4 半音；`do→fa` = +5 半音（≈ 升四度/五度，**可用**）
- `do→sol` = +7 半音（升五度）；再往上就是整八度
原曲转调量若接近四五度，直接用 `+5`/`+7` 半音级升移；接近全音就用 `+4` 近似（听感上都是「往上顶一段」）。

## 交付纪律
- **三版都渲 mp3 直接发进聊天**让用户 A/B（听感只能用户验收；`render_preview.py --bitrate 64k`）。
- 同名多版本必须带**限定词**（《X（同调版）》《X（升区版）》），否则 BetterGI 列表里重名没法分辨（§9.1）。
- 如实说明哪条路线改了什么：「A 版每个音都准但少了层层拔高，B 版保住了推进感但第 2/3 段有 N 个音挪了半音」。

### 别发全长 mp3 —— 把「有差别的那几处」剪成一段
多版对照时，用户不该在 4 个 2–3 分钟的全长 mp3 里各找一遍那几个音。
`scripts/make_ab_excerpt.py` 把指定时间窗（毫秒）剪下来、按给定间隔拼到一条新时间轴上，
每版输出一份 30 来秒的短 JSON，再 `render_preview` → 一次就能听出差别。
窗口要**框住争议点**（实测两个窗：转调段里的半音处 + 末段高潮里的半音处，共 33s）。
⚠ 窗口单位是**毫秒**（`press_intervals` 的返回单位）—— 用秒去比不会报错，只会每版只剩 3 个按键。

### 单曲反复打磨的文件纪律（一首歌会被改 5–6 版）
`scores/<曲名>/` 是这首歌的工作目录，长期这样放：
源（`.mid` + 谱图）· **每个候选版的 JSON** · 上一版/当前版的**全曲 mp3** · **短对照 mp3（对比 1..N）** · `README.md`
（结论 + 每版差异 + 数据依据）。
- 文件名写**实际做法**（`_就近挪` / `_快速滑过` / `_两键同按`），不写「新版/上一版」；
  标签写错要连文件名一起改（实测把「往上挪」写进文件名后，才发现方向其实是上下文决定的）。
- 曲库里**只留当前版**；换版 = 覆盖同一文件名 + 清掉 description 里的「【对照版】」前缀（§9.3）。
